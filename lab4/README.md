# Лабораторная работа №4. Динамическое программирование

Мурашов Никита Александрович, поток МетОпт 1.2.

Задача — пошаговое управление инвестиционным портфелем.
Условие, расчёт Беллмана, стратегия и пример сделок — в [отчёте](report.md).

## Запуск

Команды выполняются из `lab4`. Python 3.11 или новее.
Для основной программы достаточно стандартной библиотеки.

```bash
python main.py
```

Программа показывает исходный портфель, первую сделку, решения для всех наблюдаемых
рыночных ситуаций и итоговый доход. Порядок активов в управлении — ЦБ1, ЦБ2, депозит;
положительное число пакетов означает покупку, отрицательное — продажу.

При правиле `round` (по умолчанию) первое решение по критерию Байеса: купить **23 пакета ЦБ1** на 575 д.е.,
уплатить 23 д.е. комиссии, оставить 2 д.е. свободными.
Ожидаемый конечный капитал — **2033,7038838 д.е.**,
чистый доход — **133,7038838 д.е.**
Следующие сделки зависят от уже наблюдавшегося рынка.

Подробный разбор одной траектории — благоприятный, негативный, нейтральный рынок:

```bash
python main.py --scenario благоприятный негативный нейтральный
```

Для каждого этапа выводятся состояния **до сделки → после сделки → после рынка**,
комиссия и общий капитал. Доход на этой траектории — 92,25 д.е.,
он не обязан совпадать с ожидаемым доходом.

Другие критерии и короткий вывод:

```bash
python main.py --criterion wald
python main.py --criterion laplace
python main.py --criterion hurwicz --alpha 0.5
python main.py --brief
```

Критерий применяется на каждом этапе; `alpha` — вес оптимизма Гурвица от 0 до 1.
Правила расчёта описаны в отчёте.

## Аргументы

- `--criterion bayes|wald|laplace|hurwicz` — критерий. По умолчанию `bayes`.
  Байес учитывает вероятности условия; Вальд выбирает лучший худший результат;
  Лаплас считает исходы равновероятными; Гурвиц взвешивает лучший и худший результаты.
- `--alpha 0.5` — вес лучшего результата для Гурвица, от 0 до 1.
  По умолчанию 0.5; для остальных критериев не влияет на результат. Дроби вводятся через точку.
- `--minimum-rule round|trade` — момент проверки минимумов, описан ниже.
  По умолчанию `round`.
- `--scenario` — ровно три исхода по порядку раундов. Допустимы
  `благоприятный`, `нейтральный`, `негативный` (строчными русскими буквами).
  Добавляет разбор одного примера, не меняя стратегию и не сообщая ей будущее.
  Без этого аргумента отдельный пример не выводится.
- `--brief` — скрыть исходные таблицы и подробную стратегию, оставив настройки,
  первое управление и итог. Разбор `--scenario`, если задан, сохраняется.
- `--help` или `-h` — показать справку без расчёта.

Аргументы можно объединять:

```bash
python main.py --criterion bayes --minimum-rule round --brief --scenario благоприятный негативный нейтральный
```

История `благоприятный -> негативный` означает исходы первого и второго раундов.
Капитал — стоимость всех вложений плюс свободные деньги; доход — капитал минус
начальные 1900 д.е. Доход конкретного примера и ожидаемый доход — разные величины.

## Выбор правила минимальных остатков

Момент проверки минимумов в исходных материалах не закреплён однозначно.
Программа поддерживает обе трактовки:

```bash
python main.py --minimum-rule round
python main.py --minimum-rule trade
```

- `round` — минимум соблюдается после сделки и после любого исхода рынка,
  включая конец третьего раунда. Это правило по умолчанию.
- `trade` — минимум проверяется только после сделки. Рынок может опустить
  стоимость ниже минимума; следующая сделка должна его восстановить.
  После последнего рынка восстановления уже не требуется.

Правило выводится даже с `--brief` и применяется ко всем трём активам.

| Правило | Продажа пакетов ЦБ1 после благоприятного / нейтрального / негативного первого рынка | Ожидаемый чистый доход, д.е. |
|---|---|---|
| `round` | 30 / 26 / 19 | 133,7038838 |
| `trade` | 31 / 27 / 20 | 133,9888838 |

В обоих расчётах используется Байес, первое управление — (23,0,0).
Выбор правила совместим со всеми четырьмя критериями и `--scenario`.

## Как устроена программа

```text
main.py                 аргументы командной строки и запуск
portfolio/
    model.py            исходные данные, состояние, сделка и рынок
    method.py           уравнение Беллмана и оптимальная стратегия
    output.py           таблицы решений и разбор выбранной траектории
tests/
    test_method.py      полный перебор малых задач и проверки портфеля
```

Все денежные расчёты выполняются точно через `Fraction`.
В таблицах округляются только отображаемые числа.
Поиск ускоряется оценками сверху, но не ограничивает число покупаемых пакетов
и не заменяет три рыночных исхода одним средним.

все 27 конечных исходов, комиссии, запрет кредита и минимальные остатки.
Также проверяются полные названия рынков, порядок истории, пример из отчёта,
полный и краткий вывод, справка и отклонение неверных аргументов.
